Settle the core types and data structures before the logic over them, each shaped to the access paths traced through it: a lookup by key gets a map keyed by it, an ordered read an ordered structure, a value read together a single record. On a path under a stated budget or measurement, the access path is the loop's walk through memory: what one pass reads sits contiguous, a dense integer key indexes a flat array, a link between items is an index into that array, and a field one loop reads across many items gets its own typed array.
_Avoid_: a linear search by the same key repeated across call sites; parallel arrays whose elements every read takes together; a type reshaped in each commit that adds logic over it. On a budgeted path: a `Map` keyed by dense integers; an array of booleans where a bitset fits; objects linked by reference where indices into one array fit; an array of records a loop walks to read one field; a side table read on every step for a tag that fits in spare bits of the index; a temporary allocated per iteration that dies within it, where one buffer reused across passes fits.
Detect: a collection searched by one key (`.find(x => x.id === id)`, `.filter(...)[0]`) at 2+ sites or inside a loop, where a map keyed by it fits; on a budgeted path, a `Map` or object keyed by dense integers, a `boolean[]`, a loop over records that reads one field of each, or an array or object literal inside the loop body that does not outlive the iteration; a type whose fields change in most of the commits that change the logic using it.
Not-when: a collection small and fixed enough that the access shape cannot matter (a handful of config entries); a spike whose shape is the thing being found; the memory shapes on a path with no stated budget or measurement — there the logical access path decides.
