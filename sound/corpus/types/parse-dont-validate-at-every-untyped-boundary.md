Data crossing an untyped boundary (HTTP body, DB row, env var, third-party SDK response, `JSON.parse`) must be parsed into the domain type at that boundary and never trusted via a type assertion further downstream; that static type is inferred from the one schema or generated type that owns the shape, never a hand-written parallel interface.
_Avoid_: `as Order`, `as any as Order`, or a generic type parameter on `fetch`/`JSON.parse` standing in for validation; an `interface Order` hand-written beside the `OrderSchema` that parses it.
Detect: an `as <DomainType>` cast, or a bare type parameter, applied directly to the output of `fetch`, `JSON.parse`, a DB client call, or `process.env` — with no schema/parse call between the raw value and the cast; or a hand-written type or guard re-declaring the fields of a schema or generated type in the repo.
Not-when: the value already came from a parse step earlier in the same call chain and is being re-narrowed for convenience (e.g. narrowing `unknown` to a known-good local variable inside the same function that just validated it). An `any`/`unknown`-typed parameter on an INTERNAL function is not a boundary — the rule governs data entering the process (IO), not loosely-typed in-process signatures.
