A check that passes only on a second try, or only with more time, has a bug in the code, the test or the test's setup: find it. A retry, a wider timeout, a skip or a quarantine list turns the check green by hiding the failure it exists to catch. Making a suite faster or more parallel surfaces such bugs (state leaking between files, order dependence, a shared port or database); each one surfaced is a finding of the speedup, never its cost.
_Avoid_: a retry count in the test runner config; a CI step wrapped in a retry; `continue-on-error` or an allowed failure on a test job; a test or job timeout raised in the change that made the suite parallel; a skip, a todo or a quarantine-list entry whose only stated reason is "flaky".
Detect: a diff that adds or raises a retry count, a timeout, an allowed failure or a skip on a test or a CI check, and names neither the cause it found nor a measurement that the checked work itself grew.
Not-when: the retried step only fetches from a service outside the repo before any check runs (a package download, a runner image pull), so its failure says nothing about the code; or the timeout rises with a cited measurement that the work grew (more cases, a bigger fixture) — optimization-cites-a-measurement's ground, not a hidden failure.
Cross-ref: removal-names-the-fences-reason — a retry already in the code is a fence: remove it by naming the bug it hid. wait-on-a-bound-the-app-emits — the usual bug behind a check that needs more time. fail-fast-over-fail-slow — the same refusal of retries, on the request path.
