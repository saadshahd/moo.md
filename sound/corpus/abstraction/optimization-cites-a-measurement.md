Complexity added in performance's name must cite the measurement that motivated it — a profile, a benchmark, a production trace — in a comment or the surrounding diff, and a micro result counts only as its share of the end-to-end path a user waits on. Uncited perf machinery is speculative generality on the performance axis: the machinery has arrived before its trigger fired. What a measurement licenses first is a redesign of the data layout; a cache over the code's own computation comes only when the redesigned layout still misses the budget, and cites that miss.
_Avoid_: a cache, memo table, precomputation pass, or hand-tuned rewrite of a clear transformation justified by "should be faster", "could get slow", or nothing; a micro-benchmark speedup cited with no end-to-end figure beside it; a cache added over a slow layout that was never redesigned.
Detect: perf machinery — memoization, a denormalized copy, an object pool, a single-pass loop replacing a named transformation chain — with no comment or diff prose naming the measured baseline it answers, or naming only a micro result with no end-to-end figure for the path it sits on.
Not-when: the faster form costs no extra concepts (lazy-over-eager, push-work-to-the-database — structural moves that need no license); or the code sits under a stated budget (a frame loop, a documented SLO) — the budget is the measurement.
