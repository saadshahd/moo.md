sound reads your repo's stack and proposes only the rules your code shows a surface for. Each proposal names the file that earns it. The rules you confirm land as plain files in `.claude/sound/`, yours to edit.

## Skills

| Command | What it does |
| --- | --- |
| `/sound:setup` | reads your stack, proposes rules with their evidence, installs the ones you confirm |
| `/sound:prime` | has Claude read the rules for the code it is about to change |
| `/sound:review` | checks a staged diff or a commit range against your rules |
| `/sound:find` | names up to three tools for one need, each checked against sources fetched that run; Claude also runs it when it is about to pick a tool |
| `/sound:stack` | lists the steps you still do by hand, finds a tool for each, and writes the picks into `CLAUDE.md` under `## Tools` for you to review |

Run `/sound:setup` again after your stack changes. It reconciles with the rules you already have.

`find` names a tool only when an agent can run it from text, can read the result back, its license and docs check out, and its author passes. The author check cannot see a hijacked maintainer, so each pick shows the age of its latest version. `stack` installs nothing and edits no manifest.
