---
name: dissolve
description: Find a design that keeps both sides of a trade-off. Use when a trade-off is taken as forced — getting one thing is said to mean giving up another.
---

This runs inside one turn — nothing waits on the user.

1. State the trade-off in one line: what is gained, and what is given up for it.
2. Check for a limit: if the trade-off follows from a math or physics limit that binds this case — not one that only sounds near — it is real; skip to the end.
3. Name the one thing that has to be two ways at once, and what each side needs from it.
4. Find where the two needs part: a moment when only one applies, a part of the system only one touches, a condition under which only one holds, a whole that must be one way while each piece is the other. Give each need its own. Where several partings work, prefer the one that changes what exists over the one that adds a new part.
5. Test the design: each side must survive whole. A design that gives up part of either side is a compromise — discard it and try a different parting once. If the second fails the same test, the trade-off is real.
6. Name what the design newly costs: new parts, new ways to fail, new work. A design with no named cost does not ship.

Hand back three parts and nothing else: the trade-off in one line, the design, and what it newly costs. The limit check, the parting and the test stay in your working.

If the trade-off is real, hand back that verdict and why — the limit it rests on, or where each tried parting broke — and nothing after it. Let no design stand when the test showed none.

The user weighed the trade-off and chose a side → it is chosen, not forced; leave it. The ways are still open and none is said to cost another → pick among them. The user wants how named experts would see it → use **consult** skill. Every option loses because the problem itself came stated by default → use **reframe** skill.
